# 催しカレンダー更新（GitHub Actions 用の指示）

このファイルは `.github/workflows/research-business-hotel-events.yml` が Claude Code（`claude -p`）に渡す指示です。
ワークフローは、この下に「今回の実行条件」（モード・今日の日付・作業用ディレクトリ・サブエージェントのモデル）を付け足して渡します。
回答・報告は日本語で。

## 守ること

- 最初に `docs/business-hotel-events-research.md` を読み、基準・確かめ方・ファイルの形に厳密に従う。
- 変更してよいのは `data/business-hotel-price-trends/events.json` だけ（`merge` コマンドで作る）。ほかのファイルは編集しない。
- git の操作（commit・push・ブランチ作成）や PR 作成はしない。テストとコミット・公開はワークフローが行う。
- 都市ごとの作業ファイルは、実行条件の「作業用ディレクトリ」（リポジトリの外）に `<市場コード>.json` として書く。
  形は `{"market": "<市場コード>", "events": [...]}`。催しが無い都市も空の配列で書く。
- 10都市: 札幌 sapporo・仙台 sendai・名古屋 nagoya・広島 hiroshima・福岡 fukuoka・金沢 kanazawa・那覇 naha・鹿児島 kagoshima・熊本 kumamoto・岡山 okayama。

## モード full（全調査。毎週の既定）

1. 今日から60日後までに開催日が重なる「遠方から人が集まる催し」を10都市について調べる。
2. サブエージェント5つ（2都市ずつ）を並行で動かす。サブエージェントのモデルは実行条件の指定に従う。各サブエージェントには次を指示する:
   - `docs/business-hotel-events-research.md` を読む。
   - WebSearch / WebFetch で調べ、載せる催しは出典ページを実際に開いて「その年の開催日」と「会場」が書かれていることを確認したものだけ。迷ったら載せない。
   - 手順書の「毎回開く会場」の公式スケジュールのページを、担当都市の分はすべて開く（検索結果だけで済ませない）。
   - `note` に料金・満室・空室・予約・混雑の予想を書かない。
   - 今の `data/business-hotel-price-trends/events.json` にある催しのうち期間内のものも、出典をもう一度開いて確かめてから載せる。
   - 担当2都市の作業ファイルを作業用ディレクトリに書く。
3. 結果が揃ったら、各都市から2件ずつ選んで出典ページを自分でも開き、開催日と会場が合っているか抜き取り確認する。合わないものは削除する。

## モード delta（週の差分チェック。費用を抑える）

全体を一から調べ直さず、次の2つだけを行う。サブエージェントは2つ（5都市ずつ）を並行で動かす。

1. 今の `events.json` の催しのうち、終わりの日が今日以降のものは、出典ページを WebFetch で開き直し（検索はしない）、開催日と会場が変わっていないか確かめる。
   - 変わらなければそのまま残す。
   - 中止・延期・日付変更があれば、出典で確かめられた内容に直す。確かめられなければ外す。
2. 新しく探すのは次だけにする（都市ごとの検索はおおむね3回まで）:
   - 前回の調査期間の終わり（`coverage.end`）の翌日から、今日から60日後までの間に始まる催し。
   - 前回の調査後に新しく発表された、期間内の大きな催し（大きな会場の公演・全国大会など）。
   - 載せる基準と確かめ方は full と同じ（出典ページを開いて開催日と会場を確認。迷ったら載せない）。
3. 結果が揃ったら、新しく加えた催しから各都市1件ずつ（無い都市は除く）出典を自分でも開いて抜き取り確認する。

## 反映（両モード共通）

1. `python scripts/business_hotel_events.py merge <作業用ディレクトリ> --researched-on <今日の日付>` で events.json を作り直す。
   検証エラーが出たら、該当の催しを直すか外して作業ファイルを書き直し、もう一度 merge する。
2. `python -m pytest -q tests/test_business_hotel_events.py` が通ることを確かめる。
