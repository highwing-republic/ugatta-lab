# 催しカレンダーの調べ方（ビジネスホテル料金トレンド）

ビジネスホテル料金トレンドの10都市について、向こう2か月に開かれる「遠方から人が集まる催し」を週1回調べ、
`data/business-hotel-price-trends/events.json` に保存する。ページはこのファイルと料金データを突き合わせ、
急騰日・売り切れが目立つ日に重なる催しを「AI調べ・参考」として出典つきで表示する。
料金の集計・ページの数字と文には使わない。

## 調べる範囲

- 期間: 調べる日から60日後まで（料金の観測期間と同じ）。期間の前から続いている催しも、期間に重なれば載せる。
- 都市: `cohort.json` の10市場（札幌・仙台・名古屋・広島・福岡・金沢・那覇・鹿児島・熊本・岡山）。
  市内の会場に加え、その都市に泊まって通う人が多い近郊の大会場も含める（例: 北広島のエスコンフィールド、利府のセキスイハイムスーパーアリーナ、
  常滑の Aichi Sky Expo、宜野湾の沖縄コンベンションセンター、沖縄市の沖縄アリーナ）。
- 載せる催し（遠方からの来場が多いもの）:
  - `concert` ドーム・スタジアム・アリーナ（おおむね5,000人以上）の公演
  - `sports` プロスポーツの大きな試合・大相撲の本場所・全国大会・国際大会
  - `marathon` マラソン・大規模な市民スポーツ大会
  - `convention` 学会・全国大会・総会（おおむね1,000人以上）
  - `trade_show` 見本市・展示会
  - `festival` 大規模な祭り・花火大会
  - `exam` 全国規模の試験
- 載せないもの: 小規模なライブハウス公演、通常のリーグ戦の1試合（優勝決定など特別なものは可）、地元向けの小さな催し。

## 確かめ方（必ず守る）

1. 会場の公式スケジュール、主催者の公式ページ、学会の公式サイト、チケットサイト、自治体・観光協会のイベント情報などを Web で調べる。
2. 載せる催しは、出典のページを実際に開き、**開催日と会場（または開催地）が書かれていることを確認**する。検索結果の一覧の文だけで判断しない。
3. 開催日が確認できないもの、年が違うもの（前年の情報）は載せない。迷ったら載せない。
4. 文に料金・満室・空室・予約・混雑の予想を書かない（料金は別に集計しているため）。`note` は催しの説明だけを40字以内で書く。
5. 検索だけに頼らず、下の「毎回開く会場」の公式スケジュール（イベント情報）のページを必ず開いて、期間内の催しを確かめる。
   会場名は命名権などで変わることがあるので、今の名称で探す。会員限定などで見られないページは、ほかの公式の出典（主催者・チケットサイト）で確かめる。

## 毎回開く会場（公式スケジュール）

都市ごとに、遠方から人が集まる催しの多い会場。ここに無い会場の催しも、基準に合えば載せる。

- 広島: 広島グリーンアリーナ、広島国際会議場、マツダスタジアム、エディオンピースウイング広島

- 岡山: ジップアリーナ岡山、岡山コンベンションセンター、シティライトスタジアム

## ファイルの形

```json
{
  "schema_version": 2,
  "researched_on": "2026-10-16",
  "coverage": {"start": "2026-10-16", "end": "2026-12-15"},
  "events": [
    {
      "market": "naha",
      "name": "第42回 NAHAマラソン",
      "start": "2026-12-06",
      "end": "2026-12-06",
      "venue": "奥武山公園発着",
      "category": "marathon",
      "note": "定員3万人の市民マラソン",
      "sources": [{"url": "https://...", "title": "ページの題名"}]
    }
  ]
}
```

- `market` は `cohort.json` の市場コード。`start`・`end` は催しの開催日（1日だけなら同じ日）。
- `sources` は1〜2件。確認したページのURLをそのまま入れる。
- 毎回、ファイル全体を作り直す（前回の催しで期間内のものも、もう一度確かめてから載せる）。
- 書いたら `python -m pytest -q tests/test_business_hotel_events.py` で形式を確かめる。

## 週1回の更新

GitHub Actions の `.github/workflows/research-business-hotel-events.yml` が毎週日曜の夜（21:47 JST）に動き、
Claude Code（`claude -p`、費用は Claude API）がこの手順で調べてファイルを作り直す。指示は `docs/business-hotel-events-ci-prompt.md`。
テストが通れば main に反映して公開する。1回の費用・Claude の報告はジョブの概要に出る（2026-10-19 の全調査で約3ドル）。
手動で更新するときは、Actions の画面からこのワークフローを実行する（`delta` は費用をさらに抑えたいときの差分チェック）。
リポジトリシークレット `ANTHROPIC_API_KEY` が必要。
